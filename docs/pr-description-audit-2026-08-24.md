## 対応方針

新規PRには、次の仕組みを適用済みです。

- `.github/pull_request_template.md`で7区画を自動提示する。
- `scripts/verify-pr-description.ts`で見出し順、空区画、改行、文字列化`\n`、末尾空白をfail-closed検査する。
- `quality.yml`のPR品質検査で本文を検証する。
- `pr-trust-gate`はbase側の検証器からGitHub APIで本文を再取得し、PRブランチ側の検証器変更では回避できない経路で検証する。
- `docs/pull-request-guidelines.md`と`AGENTS.md`へ本文ルール、レビュー観点、既存PRの見直し手順を記載する。

既存PR本文の移行は、本文の意味を変えないことを優先します。移行時は改行をLFへ正規化し、既存見出しを7区画へ再配置し、分類できない区画は「移行前区画」として変更内容へ保持します。検証結果やレビュー判定は推測で補いません。

監査時点では、既存PR本文の一括書き換えは実施していません。Merged / Closedを含む履歴本文の直接更新は、分類誤りや情報欠落の影響を確認したうえで、対象範囲を明示して段階的に実施します。Open PRは、本文更新前にstate、base、head SHA、CI状況を再取得します。
