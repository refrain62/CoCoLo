## 確認項目

### 1. 現行と将来の境界

- Supabase Auth は現行利用中、Supabase PostgreSQL は現行のアプリDB、Cloudflare R2 は Phase 4 導入予定として区別されている。
- DB分離後も Auth とアプリDBを別責務として扱い、Authスキーマやパスワード情報をアプリDBへ移行しない契約になっている。
- R2の秘密情報、DB URL、Service Role Keyをブラウザへ渡さない境界が運用仕様・環境変数説明・配置契約に記載されている。

### 2. テナント越境・認可・個人情報

- `user_id` はAuthの外部識別子として文字列保持し、Auth内部テーブルへの外部キーを作らないため、DB分離時に認証基盤をDBダンプへ巻き込まない。
- RLS、`cocolo_app`、migration owner、security ownerを分離し、`rolbypassrls=false`を分離後の実クエリで確認する手順がある。
- 接続プールでテナントコンテキストが残留しないよう、トランザクションローカル設定とテナントA/Bの越境拒否を検証対象にしている。
- dump対象のallowlistと対象外schemaを明記し、秘密情報・Auth内部データ・管理用schemaを移行対象から除外している。

### 3. 状態遷移・冪等性・整合性

- 年度繰り上げの `idempotency_key`、監査ログの時系列、外部ユーザー識別子を照合対象にしている。
- 新DBへの書き込み後に接続先だけを戻す盲目的な切り戻しを禁止し、差分照合とforward recoveryを要求している。
- R2は未実装であり、将来導入時も添付メタデータとオブジェクト本体の照合をDB復旧と分離して行う契約になっている。

### 4. 本番運用・障害対応

- backup取得だけでなくrestore訓練、RPO/RTO、監視、接続数、lock待ち、TLS、秘密情報ローテーションを確認対象にしている。
- 外部サービス障害時に、認証検証の無効化、公開バケット化、別環境DBへの接続を回避策として禁止している。
- 配置アダプターは成果物SHA、環境、HTTPS URL、配置時刻、配置記録を検証し、証跡不備時に昇格を停止する契約になっている。

## 未実施・導入前の停止条件

次の項目は仕様上の未決定事項であり、実装済み・運用済みとは扱わない。

- 分離先DBのベンダー、リージョン、PostgreSQL版、ネットワーク方式
- 業務責任者が承認したRPO/RTO、停止可能時間、バックアップ保持期間
- 実データ量に対するdump/restoreまたは別移行方式の選定
- Cloudflare R2の実バケット、CORS、署名鍵、削除クリーンアップの導入
- 配置先サービス固有のアダプター実装と、部分配置からの復旧手順

これらはDB分離仕様の導入判定に記載した承認条件を満たすまで、本番切り替えを行わない。
