# 日本語表記ガイド

CoCoLo の画面、エラーメッセージ、運用ログ、技術文書で使う日本語の基準です。新しい機能や文書を追加するときも、この基準で表記を確認します。

## 基本方針

- 一文には一つの操作または判断だけを記載し、長い文は分けます。
- 主語と対象を省略しすぎず、利用者が次に何をすべきか分かる表現にします。
- エラーメッセージは、原因または不足している設定と、必要な対応を短く示します。
- 画面文言と API の説明は、文末の句点を含む完全な文にそろえます。見出しや表の項目名は簡潔な名詞句で構いません。
- 自明な処理へのコメントは追加せず、前提・制約・競合対策などコードから読み取りにくい意図だけを近くに記録します。

## 用語

| 表記 | 使い方 |
| --- | --- |
| 利用者 | CoCoLo を使う人全般。画面文言では「ユーザー」と混在させません。 |
| オーナー、管理者、スタッフ、保護者 | 画面で権限を説明するときの日本語。API の値は `owner`、`admin`、`staff`、`guardian` と記載します。 |
| 開発環境、検証環境、本番環境 | `local`、`staging`、`production` の説明。設定値そのものはコード表記で残します。 |
| 成果物 | 配布・配置するリリースファイル。`artifact` とだけ書きません。 |
| 配置アダプター | 環境固有サービスへ成果物を配置する処理。`deploy adapter` とだけ書きません。 |
| テストデータ | テスト用に投入するデータ。`fixture` とだけ書きません。 |
| リクエスト、レスポンス、ストレージ、セッション | 一般的な技術用語としてカタカナで統一します。 |

## 表記チェック

レビューでは、次の点を確認します。

- 画面の権限説明と API の認可条件が一致している。
- 設定値・API 項目・状態値はコード表記を維持し、説明側に日本語の意味がある。
- 英語と日本語の間に必要な空白があり、同じ用語の表記が文書間で揺れていない。
- 警告や失敗条件が先に示され、利用者または運用者の対応が分かる。
- 変更した文言に対応するテスト、生成物、運用文書を更新している。
