## 1. この文書の役割

この文書は、CoCoLo が利用者に提供する機能、業務ルール、権限、状態遷移、受け入れ条件を定義する「何を作るか」の正本です。

* `docs/functional-specification.md`: 機能・業務仕様の正本。改修指示は機能仕様 ID を指定します。
* `docs/ implementation-plan.md`: 技術方式、実装フェーズ、テスト、環境、CI の計画。

仕様にない挙動を実装者の判断だけで追加せず、先にこの文書を更新します。仕様変更時は版、変更理由、影響する機能仕様 ID、データ移行の要否を記録します。

## 2. 用語と利用者

| 用語 | 定義 |
| --- | --- |
| チーム | CoCoLo を利用する部活・クラブチーム。データ分離の単位。 |
| 部員 | チームに所属する選手または一般参加者。 |
| 保護者 | 部員に紐づき、対象部員の情報確認や出欠回答を行う利用者。 |
| 役員 | 会長、会計、配車担当など、年度単位でチーム運営を担当する利用者。 |
| 管理者 | チーム設定、所属、部員、購買、個人情報を管理する権限を持つ利用者。 |
| スタッフ | 指導者・運営担当。予定や出欠の運用を行うが、個人情報と設定を管理しない。 |

### 2.1 権限

| 操作 | owner | admin | staff | guardian |
| --- | --- | --- | --- | --- |
| チーム・所属管理 | すべて可 | 運用可、owner変更不可 | 不可 | 不可 |
| 部員の全件閲覧 | 可 | 可 | 可 | 担当部員のみ |
| 部員の登録・編集・退部 | 可 | 可 | 不可 | 不可 |
| 予定・出欠の運用 | 可 | 可 | 可 | 担当部員の回答 |
| 電話番号・特記事項の閲覧 | 可 | 可 | 不可 | 不可 |
| 購買・支払い確認・CSV | 可 | 可 | 不可 | 自分の注文確認のみ |
| 監査履歴の閲覧 | 可 | 不可 | 不可 | 不可 |

別チームのデータ、担当外部員の情報、権限外の個人情報は、存在の有無を推測できない形で拒否します。

## 3. 共通業務ルール

### FS-COM-001 チーム分離

すべての情報はチーム単位で管理し、利用者は有効な所属を持つチームだけを操作できます。画面からチーム ID を書き換えても、別チームの情報を閲覧・変更できません。

### FS-COM-002 日時・年度

保存・判定の基準時刻は UTC、画面表示は `Asia/Tokyo` とします。年度は日本の年度（4月1日〜翌年3月31日）として扱います。締切判定はクライアント時刻ではなくサーバー時刻で行います。

### FS-COM-003 個人情報

氏名、ふりがな、電話番号、保護者との関係、特記事項は必要な権限へ最小限だけ表示します。閲覧、CSV出力、変更、退部処理は監査履歴へ記録します。Phase 1 の通常部員登録では特記事項を入力できません。

### FS-COM-004 状態と削除

利用中データは原則として物理削除せず、退部・停止・無効化などの状態で管理します。物理削除や匿名化が必要な場合は、保持期間と責任者の承認を確認してから実行します。

### FS-COM-005 資源IDとURL

API と画面 URL の資源 ID は連番ではなく UUIDv7 とします。UUID の値を知っていることだけでは認可にならず、すべての要求でログイン状態、所属チーム、役割、担当範囲を検証します。一覧や履歴の表示順は `createdAt` を正本とし、同じ時刻の並びを UUIDv7 で安定化します。UUIDv7 の生成時刻が推測できることを理由に、個人情報や別チームの存在を返してはいけません。

## 4. 認証・チーム利用

### FS-AUTH-001 ログイン

利用者は Supabase Auth でログインします。未ログイン状態では認証が必要な画面・操作を利用できません。期限切れ・署名不正・停止済み所属はログイン済みでも操作を拒否します。

### FS-AUTH-002 チーム選択

複数チームに所属する利用者は、操作対象チームを明示的に選択します。選択中のチーム名と役割を共通ヘッダーに表示します。

### FS-AUTH-003 所属状態

所属状態は `invited → active → suspended` と遷移します。`suspended` はログインできてもチームデータを操作できません。最後の owner を削除・降格できません。

## 5. 部員管理（Phase 1 MVP）

### FS-MEM-001 部員一覧

owner、admin、staff は所属チームの部員を一覧できます。検索対象は氏名・ふりがな、絞り込みは category・status とします。guardian は紐づく部員だけを一覧できます。

一覧には氏名、ふりがな、区分、学年または年代、status を表示します。電話番号、保護者識別子、特記事項は staff と guardian に表示しません。

### FS-MEM-002 部員登録

owner または admin は氏名、ふりがな、区分、学年または年代、status を入力して部員を登録できます。チーム ID、部員 ID、作成日時、特記事項は利用者入力ではなくシステムが管理します。

必須条件:

* student は `gradeLevel` または仕様で定めた学年情報を持つ。
* adult は `ageGroup` を使用し、学年表示を要求しない。
* 名前は空文字・過剰な長さを拒否する。
* status の初期値は `active`。

### FS-MEM-003 部員編集・退部

owner または admin は部員の基本情報を編集できます。通常の編集で変更できる status は `active` と `suspended` です。退部は専用の退部操作で `retired` へ遷移し、既に retired の部員に同じ操作をしても結果は変わりません。

退部後の部員は通常一覧から非表示にできますが、管理者は履歴として検索できます。退部処理では変更前後の status、実行者、時刻を監査します。

### FS-MEM-004 学年表示

`formatGrade` の表示規則は次のとおりです。

| gradeLevel | 表示 |
| --- | --- |
| 1〜6 | 小1〜小6 |
| 7〜9 | 中1〜中3 |
| 10〜12 | 高1〜高3 |
| 13〜16 | 大1〜大4 |
| 17以上 | OB / 院生 |

category が adult の場合は gradeLevel ではなく ageGroup を表示します。

### FS-MEM-005 年度繰り上げ

owner または admin は年度末に、対象年度と実行内容を確認して繰り上げを実行できます。対象は `active` かつ `student` の部員だけで、gradeLevel を一度だけ +1 します。adult、retired、suspended は対象外です。

実行前の `preview` で対象件数を表示し、`execute` は `Idempotency-Key` を必須とします。同一チーム・同一年度の二重実行は保存済み結果を返す no-op とし、同一keyのrequest hashが異なる再送は拒否します。`PromotionRun` は `preview → completed/failed`、失敗時の再試行は `failed → completed/failed` だけを許可します。17以上の表示、卒業・留年・退部の扱いは実行前の確認画面に表示します。

## 6. 予定・出欠（Phase 2）

### FS-EVT-001 予定登録

owner、admin、staff は予定を登録・編集できます。予定はタイトル、種別（練習・試合・イベント）、開始・終了時刻、場所、持ち物、会費、案内画像、出欠締切を持ちます。試合では対戦相手、遠征では集合時刻と配車要否を追加できます。

### FS-EVT-002 予定表示

月間・週間表示を切り替えられます。練習は青、試合は赤、イベント・懇親会は紫で識別します。スマートフォンではカードまたは横スクロールで内容を確認できます。

### FS-EVT-003 出欠回答

guardian は担当部員の出欠を、出欠締切前に `attending`、`absent`、`pending` のいずれかで登録・変更できます。部員本人の直接ログイン・回答は Phase 1〜5 の対象外です。締切後は guardian の変更を拒否し、owner、admin、staff は管理操作として修正できます。締切後の修正理由と実行者を監査します。

同一イベント・同一利用者・同一部員の回答は1件に統合します。管理者はチーム内の回答数と未回答者を確認できます。

## 7. 役員・連絡先（Phase 3）

### FS-BRD-001 年度役員

owner または admin は年度、役職名、担当者、role type を管理できます。新年度には前年度の役職枠だけを複製し、担当者・個人連絡先は自動コピーしません。

### FS-BRD-002 連絡先表示

電話番号の表示設定は `line`、`phone`、`both` から選択します。`line` は電話番号を表示せず、`phone` は電話番号を表示し、`both` は両方を表示します。表示できるのは権限を持つ利用者だけです。

## 8. 共同購買・集金（Phase 3）

### FS-ORD-001 商品・選択肢

owner または admin は募集案件、商品、価格、画像、任意の選択肢を登録できます。選択肢は商品ごとに定義し、キッズサイズ、大人サイズ、フリーサイズなどを混在させられます。注文時の選択値は登録済み選択肢に限ります。

### FS-ORD-002 注文

guardian は対象部員、自分の注文者情報、商品、選択肢、数量、背番号、背ネームを入力できます。数量は1以上、背番号・背ネームは商品の入力条件に従います。別チームの商品や別注文の商品明細は登録できません。

### FS-ORD-003 集金

オンライン決済は使用せず、現金手渡しまたは銀行振込の確認状態を管理します。owner / admin は未払いから支払い済みへ切り替え、確認日時と確認者を記録できます。支払い済みを未払いへ戻す場合も監査します。

### FS-ORD-004 集計・CSV

管理者はサイズ・選択肢別の数量、支払い状態、未払い者を確認できます。CSV は UTF-8 BOM 付きとし、セル先頭の `=`, `+`, `-`, `@` を式として実行されない形式に変換します。

## 9. 添付・回覧・通知（Phase 4）

### FS-FIL-001 添付

添付ファイルはチーム専用の private storage に保存します。許可形式、magic bytes、実体サイズを検証し、SVG は受け付けません。利用者へ公開URLを保存・配布せず、権限確認後に短期URLでダウンロードさせます。

### FS-FIL-002 添付アップロードの手順

利用者が添付を開始すると、API は所属・権限・許可 MIME・最大20 MiBを確認し、TTL 900秒の一回限り upload session と署名URLを発行します。Web は署名URLで private storage へ直接 PUT し、API の `complete` 操作を呼び出します。API は session の所有者、チーム、object key、期限、未使用、上書き不可、実体サイズ、magic bytes、sha256 を再検証します。complete の再試行は同一 session で3回までです。検証成功時だけ `uploaded → available` とし、期限切れ、再利用、別チーム、改ざん、形式不正は `rejected` として24時間以内に保存本体を削除します。

### FS-ANN-001 回覧板

owner、admin、staff は連絡事項と PDF 等の資料を掲載できます。利用者は本文と添付を確認し、確認時刻を記録します。掲載者は未読者一覧を確認できます。

### FS-NOT-001 LINE通知

LINE連携が設定されたチームだけ、予定・締切・回覧の通知を送信します。未設定はエラーではなく「未接続」と表示し、送信失敗は再送可能な状態で記録します。Webhook は署名・重複・対象チームを検証します。

## 10. 送迎（Phase 5）

### FS-RIDE-001 配車希望

利用者は車を出せるか、乗車可能人数、乗車希望を登録できます。管理者は希望人数と容量を確認し、手動または補助機能で割り当てます。割当結果、未割当、変更履歴を利用者へ表示します。

## 11. 状態遷移

### FS-STATE-001 状態遷移の正本

| 対象 | 状態 | 遷移条件 |
| --- | --- | --- |
| 所属 | invited → active | 招待受諾・管理者承認 |
| 所属 | active → suspended | 管理者が停止 |
| 部員 | active ↔ suspended | 管理者の状態変更 |
| 部員 | active / suspended → retired | 退部操作 |
| 出欠 | pending ↔ attending / absent | 締切前の回答 |
| 注文 | open → closed → completed | 締切・発注完了 |
| 集金 | unpaid ↔ paid | 管理者の確認 |
| 年度繰り上げ | preview → completed / failed、failed → completed / failed | owner/adminのexecute、同一年度の再実行は保存済み結果 |
| 添付 | uploaded → available → deleted | 検証成功・認可・削除 |
| 添付 | uploaded → rejected | magic bytes・サイズ・形式の検証失敗 |

状態遷移にない直接変更、利用者による状態の書き換え、締切後の本人変更は許可しません。`deletedAt` は deleted のときだけ設定し、rejected は配信・署名URL発行の対象にしません。

## 12. 画面共通仕様

* loading、空データ、入力エラー、通信エラー、権限不足、保存成功を区別して表示します。
* 必須項目、エラー理由、フォーカス位置、キーボード操作を利用者が確認できます。
* 色だけで状態を伝えず、ラベルやアイコンを併用します。
* 個人情報を含む操作、退部、支払い状態変更には確認を求めます。
* local、staging、production の環境名を画面または管理情報で識別でき、staging のデータを本番と誤認させません。

## 13. 受け入れ条件

### FS-ACCEPT-001 受け入れ条件の正本

* FS-COM-001 に反する別チームの閲覧・変更ができない。
* FS-AUTH-001〜003 の認証、所属、停止状態がすべて検証される。
* FS-MEM-001〜005 の部員一覧、登録、編集、退部、学年表示、年度繰り上げが権限・状態遷移どおりに動作する。
* FS-EVT-001〜003 の予定、締切前出欠、締切後拒否、集計が動作する。
* 個人情報の表示範囲、監査、添付の private 配信、CSV の安全性が確認できる。
* local でTDD、staging で結合・E2E、本番で承認済みartifactの昇格が行える。
