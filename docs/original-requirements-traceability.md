# CoCoLo 当初要求トレーサビリティ

更新日：2026-08-25

## 1. この文書の役割

この文書は、企画初期の会話に含まれる利用者要求、会話中の提案、後続設計で変更した事項を区別し、現行仕様への反映先を示す台帳です。

会話中に提示された実装例や推奨案を、そのまま確定仕様とは扱いません。

利用者が明示した目的と選択を「要求」、アシスタントが補った案を「提案」、現行設計で安全性や実装順序を確定した内容を「現行決定」として記録します。

機能と業務ルールの正本は[機能仕様書](functional-specification.md)、技術方式と実装順序の正本は[実装計画書](%20implementation-plan.md)です。

## 2. 当初の目的

CoCoLo は、子どものクラブで行う練習予定、試合のお知らせ、参加募集、送迎調整、回覧を Web アプリで一元管理するためのサービスです。

LINE は通知と入口に使用し、予定、回答、割当、既読、集金状態の正本は Web アプリに置きます。

複数のチームが同じサービスを利用しても、所属、個人情報、予定、注文、添付、通知先が混ざらないマルチテナント構成を前提とします。

名称には、選手、保護者、役員、指導者が「心をひとつに」してチームを運営・応援できるようにという想いを込めています。

**CoCoLo** は、「Co-（共に）」、「Co-（協力する）」、「Local / Team（地域・チーム）」を組み合わせ、**Co-operation（協力）**と **Co-ordination（調整）**を表す名称です。

## 4. 会話中の提案をそのまま採用しない項目

### 4.1 役員と操作権限

役員への就任を理由に、チームの `owner`、`admin`、`staff` を自動付与しません。

役職は年度単位の業務担当であり、操作権限はテナント所属の認可情報だからです。

権限変更は別操作として実行し、最後の owner、変更者、変更前後を監査します。

### 4.2 保護者と部員の紐付け

保護者が公開一覧から子どもを選ぶだけで紐付けを確定する方式は採用しません。

同姓同名の誤選択と、第三者によるなりすましを防ぐ必要があるためです。

紐付けはチーム管理者の招待または確認を経て確定し、利用者へ別チームや担当外部員を候補表示しません。

### 4.3 添付ファイルの公開 URL

R2 の公開 URL を DB に保存して配布する方式は採用しません。

添付は非公開バケットへ保存し、毎回の認可後に短期 URL を発行します。

### 4.4 役員連絡先

`contactPreference` が `phone` または `both` であることだけを電話番号の閲覧根拠にしません。

本人の表示希望に加えて、閲覧者の権限と同一チーム所属を検証します。

### 4.5 配車の自動確定

自動計算だけで子どもの乗車割当を確定しません。

定員、兄弟関係、チャイルドシート、運転者都合など、初期データだけでは判定できない条件があるためです。

自動処理は割当案の作成までとし、管理者が確認してから公開します。

### 4.6 無償運用

特定時点の無料枠の数値を長期保証として扱いません。

料金、上限、休止条件は変更されるため、配置前に公式情報を確認し、使用量と予算超過を監視します。

無料枠の休止を避けることだけを目的とした定期アクセスは、提供条件と運用費を確認してから採否を決めます。

## 5. 未確定事項

次の項目は会話中に提案されたものの、利用者要求として確定していません。

- 懇親会で大人と子どもの参加人数を分けて回答する方式。
- イベント会費を共同購買の集金へ自動登録する方式。
- LINE の通知先をグループ、公式アカウント、個別通知のどれにするか。
- LIFF を必須の入口とするか、通常ブラウザの deep link も同等に扱うか。
- 当番回数の公平性を自動評価し、自動割当まで行うか。
- 送迎割当に必要な安全条件と、誰がその情報を閲覧できるか。
- PayPay など個人間送金を集金方法として記録するか。
- Cloudflare Workers へ API を移行する時期と Prisma の接続方式。

未確定事項は、責任者が業務ルールと受け入れ条件を承認してから機能仕様 ID を追加または更新します。

## 6. 反映漏れを防ぐ確認手順

当初要求を変更するときは、次の順序で確認します。

1. この台帳で要求、提案、現行決定を区別します。
2. 機能仕様書の対象 ID、権限、状態遷移、受け入れ条件を更新します。
3. 実装計画のフェーズ、データモデル、API、画面、テストを更新します。
4. テナント越境、認可、個人情報、入力検証、競合、監査、外部サービス障害を敵対的に確認します。
5. 実装と文書の状態を再開タスクリストへ記録します。
